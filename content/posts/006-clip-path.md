切角是这套界面的基本粒子：能按的东西切掉一个角，不能按的保持直角。看点几秒就能分出按钮和栏目。但这东西有个著名的坑——<code>clip-path</code> 会把 border 一起切掉，你永远得不到一根完整的描边。

## 一、双层法（本站采用）

外层元素充当「边框色」，内层收缩 1px 再切一次。两层用同一切角半径时，斜边处的描边约为 1.4px，肉眼几乎看不出来。换边框色只需要改外层的背景。

```html
<div class="panel">
  <div class="panel-in">内容…</div>
</div>
```

```css
/* 同一个切角变量，外层是边框，内层是内容 */
.panel {
  background: var(--rule);
  padding: 1px;
  clip-path: polygon(0 0, calc(100% - 12px) 0, 100% 12px,
    100% 100%, 12px 100%, 0 calc(100% - 12px));
}
.panel-in {
  background: var(--panel);
  clip-path: inherit;
}
```

## 二、drop-shadow 投影

投影会跟随切角后的轮廓，叠多层零位移、零模糊的投影可以模拟 1px 描边。代价是性能：层数一多，滚动就开始掉帧。适合少量关键元素。

## 三、SVG 描边

像素完美，但维护成本高：切角半径改一次，要同步多处路径。适合设计系统里固定的图形，不适合满页的列表。

## 四、渐变拼边

用四段线性渐变拼出 1px 的边并挖掉角。只支持简单切角，缩放时还会出现亚像素断裂。不推荐，但面试时会加分。

:::note 经验
切角半径不超过元素短边的四分之一，全站只允许一到两种。每个组件一个切角的设计稿，最后一定失控。
:::

## 切角多大

小部件 7px，按钮 8px，看板 26px，画框 52px。四个档位对应四种尺寸，全站不再有第五个值。切角越大，旁边的内边距也要跟着加——文字压进斜边是最常见的事故，尤其在这套界面大量使用小号标签的时候。

切角只出现在能按的东西上：标签、筛选块、按钮、当前项。正文、图片、栏目一律直角。看形状就知道能不能点，比加一个手型光标可靠。

> 形状本身就是交互提示。
